# Dynamic XI registry: whole-branch review (2026-10-02)

Reviewer: codex gpt-6.1-sol xhigh, read-only, on `c91ca276` vs `joske/master`. Coordinator spot-checked the Xorg citations for findings 3, 5, 6, 7 and 13 (all match). Fixes are applied in three rounds: R1 = 1, 2, 8, 10; R2 = 3, 5, 6, 7; R3 = 4, 9, 11, 12, 13 + observations.

I found **nine major integration defects and four minor wire defects**. These are verified source traces against `joske/master` and `../xserver`; no files were changed and no tests were run.

1. **Major — Held keys survive detach/removal and contaminate reused IDs.** [backend.rs:11968](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver/src/kms/render/backend.rs:11968) initializes floating keyboard held state empty. Press Shift, grab that keyboard, then release Shift: the floating guard rejects the release before `commit_key_transition`. Removal retries the same rejected release, then [server.rs:1941](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver-core/src/server.rs:1941) unregisters without clearing `key_down_by_device`. A replacement keyboard reusing that ID loses its first Shift press. Ungrab/disconnect also leave stale state. Xorg preserves slave holds during grab detachment ([events.c:1470](/home/ariel_santangelo/Projects/xserver/dix/events.c:1470)) and subsequently clears the release with `set_key_up` ([exevents.c:938](/home/ariel_santangelo/Projects/xserver/Xi/exevents.c:938)).

2. **Major — Button cleanup applies mapping twice.** [backend.rs:19766](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver/src/kms/render/backend.rs:19766) interprets logical held-button bits as physical buttons. With `SetPointerMapping [3,2,1,4,5,6,7]`, physical left press holds logical button 3. Unplug/VT cleanup synthesizes physical right release; [pointer_fanout.rs:470](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver-core/src/core_loop/pointer_fanout.rs:470) maps it back to button 1, whose release guard rejects it. Master button 3 remains held and clients never receive its release. Xorg releases physical held buttons through `GetPointerEvents(..., ButtonRelease, i, ...)` ([devices.c:2640](/home/ariel_santangelo/Projects/xserver/dix/devices.c:2640)).

3. **Major — XTEST releases end another source’s passive grab.** [pointer_fanout.rs:3400](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver-core/src/core_loop/pointer_fanout.rs:3400) ends the master passive grab when the *generating slave* has no buttons held. Hold physical button 1 under an async core passive grab, then inject an XTEST4 click: aggregation correctly keeps master button 1 down, but the XTEST release clears the grab and paired freeze holds. Subsequent drag motion escapes. Xorg tests the grabbed device’s `!b->buttonsDown` ([exevents.c:1935](/home/ariel_santangelo/Projects/xserver/Xi/exevents.c:1935)), after its master aggregation guard.

4. **Major — SlaveSwitch baselines disagree with master scroll values.** [pointer_fanout.rs:2094](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver-core/src/core_loop/pointer_fanout.rs:2094) emits the global counter for master scroll events, while SlaveSwitch carries the source facet’s counter. After mouse A scrolls +10, mouse B’s first +1 announces baseline 0 but emits master value 11: a master consumer calculates +11. Xorg takes the baseline from the slave’s `axisVal` ([getevents.c:286](/home/ariel_santangelo/Projects/xserver/dix/getevents.c:286)) and copies that slave event to the master ([mieq.c:423](/home/ariel_santangelo/Projects/xserver/mi/mieq.c:423)).

5. **Major — A slave grab can freeze the master keyboard.** [pointer_fanout.rs:2919](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver-core/src/core_loop/pointer_fanout.rs:2919) applies paired synchronization to slaves. `XIGrabDevice(mouse6, Async, paired=Sync)` freezes normal keyboard delivery through master 3. Xorg explicitly forces slave paired mode to Async ([xigrabdev.c:89](/home/ariel_santangelo/Projects/xserver/Xi/xigrabdev.c:89)): `if (!IsMaster(dev)) ... = GrabModeAsync`. Its shared synchronization helper also requires `IsMaster(thisDev)`. The new [test at process_request.rs:63613](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver-core/src/core_loop/process_request.rs:63613) currently asserts the incompatible freeze.

6. **Major — Exact pointer grabs drop buttons without separate selections.** [pointer_fanout.rs:2053](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver-core/src/core_loop/pointer_fanout.rs:2053) requires a matching `XISelectEvents` selection even for grab delivery. Successfully grab a physical pointer with `owner_events=false` and a button/motion mask, without separately selecting it: press/release disappear because neither slave nor floating master form qualifies; motion arrives with device ID 2 instead of the grabbed ID. Xorg uses the grab’s mask directly: `GetXI2MaskByte(grab->xi2mask, dev, evtype)` ([events.c:4308](/home/ariel_santangelo/Projects/xserver/dix/events.c:4308)).

7. **Major — Floating pointers still generate master raw events.** [pointer_fanout.rs:3766](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver-core/src/core_loop/pointer_fanout.rs:3766) collects master raw recipients regardless of attachment. Move a physical pointer detached by `XIGrabDevice`: an unrelated root listener selecting master 2 or `XIAllMasterDevices` receives `RawMotion(deviceid=2, sourceid=6)`. Xorg’s master-copy path returns immediately for `IsFloating(sdev)` ([mieq.c:397](/home/ariel_santangelo/Projects/xserver/mi/mieq.c:397)).

8. **Major — XTEST input to a floating keyboard changes master held state.** [key_fanout.rs:184](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver-core/src/core_loop/key_fanout.rs:184) omits the attachment guard for XTEST slave transitions. Grab a physical keyboard, then inject a device key press targeting it: floating XKB changes, but master `keys_down` also changes. QueryKeymap reports the floating key, and the next attached press of that key is suppressed. Xorg’s floating-device exclusion cited above prevents this master transition.

9. **Major — Nested XTEST pointer input loses its identity.** [host_x11/trait_impl.rs:108](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver-core/src/host_x11/trait_impl.rs:108) and `:165` replace the supplied XTEST origin with `NestedHost`. Ordinary injection therefore produces only master `(deviceid=2, sourceid=2)` forms; exact-4 selections/grabs miss it. Keyboard injection preserves its origin. Xorg routes ordinary injection through `GetXTestDevice(dev)` ([xtest.c:351](/home/ariel_santangelo/Projects/xserver/Xext/xtest.c:351)).

10. **Minor — RECORD invents suppressed master transitions.** [backend.rs:19673](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver/src/kms/render/backend.rs:19673) records accepted slave keys even when `master_accepted=false`. Press the same key on two keyboards: core delivery contains one press, but RECORD contains two nonrepeat core presses. Floating keys and aggregated pointer buttons have analogous behavior. Xorg rejects suppressed transitions before its callback ([exevents.c:1851](/home/ariel_santangelo/Projects/xserver/Xi/exevents.c:1851)); RECORD converts to core only for `IsMaster` ([record.c:784](/home/ariel_santangelo/Projects/xserver/record/record.c:784)).

11. **Minor — Hotplug hierarchy descriptors contradict queries.** [hotplug.rs:257](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver-core/src/xinput/hotplug.rs:257) reports masters attached to themselves: 2→2 and 3→3, while XIQueryDevice reports 2→3 and 3→2. A grabbed floating slave also retains slave `use` instead of `XIFloatingSlave` when another device hotplugs. Xorg shares `GetDeviceUse` between hierarchy/query encoding and uses the paired master’s ID ([xiquerydevice.c:518](/home/ariel_santangelo/Projects/xserver/Xi/xiquerydevice.c:518)).

12. **Minor — Child-window DeviceChanged selections miss source switches.** [hotplug.rs:165](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver-core/src/xinput/hotplug.rs:165) requires selection on the root. Select DeviceChanged on a child, then alternate physical pointers: no SlaveSwitch arrives. Xorg calls `SendEventToAllWindows` ([exevents.c:760](/home/ariel_santangelo/Projects/xserver/Xi/exevents.c:760)), including interested children.

13. **Minor — XI1/XI2 hotplug ordering is reversed.** [backend.rs:20351](/home/ariel_santangelo/Projects/yserver-xi-dynamic-registry/crates/yserver/src/kms/render/backend.rs:20351) queues hierarchy before presence. A client selecting both receives XI2 first for each transition. Xorg sends presence first, then hierarchy ([devices.c:616](/home/ariel_santangelo/Projects/xserver/dix/devices.c:616)); Enabled, Disabled and Removed follow the same order. Added→Enabled and Disabled→Removed sequencing itself is correct.
